# การออกแบบฐานข้อมูลตามหลักการ 6 ระยะ

## ระยะที่ 1 การวางแผนฐานข้อมูล (Database Planning)

### วัตถุประสงค์

เพื่อพัฒนาระบบฐานข้อมูลกลางสำหรับจัดเก็บและบริหารจัดการข้อมูลสารสนเทศ บุคลากร นักศึกษา ผลงาน ข่าวสารกิจกรรม ทุนการศึกษา ตารางเรียน/ตารางสอบ และประวัติการฝึกงาน ของหลักสูตรวิศวกรรมคอมพิวเตอร์ สถาบันเทคโนโลยีพระจอมเกล้าเจ้าคุณทหารลาดกระบัง วิทยาเขตชุมพรเขตอุดมศักดิ์ ให้มีความถูกต้อง เป็นศูนย์กลางข้อมูลที่เข้าถึงง่าย รวดเร็ว และปลอดภัย

### ขอบเขตของระบบ

- บริหารจัดการและแสดงข้อมูลอาจารย์ประจำสาขาและบุคลากร (Teachers & Staff)
- บริหารจัดการข้อมูลนักศึกษาทุกชั้นปี สายรหัส และตำแหน่งในชั้นเรียน (Students & Cohorts)
- จัดเก็บและเผยแพร่ผลงานวิชาการ/โครงงานของนักศึกษา (Student Works)
- เผยแพร่ข่าวสารประชาสัมพันธ์ ข่าวการแข่งขัน และทุนการศึกษา (News & Scholarships)
- จัดเก็บและแสดงตารางเรียนประจำภาคการศึกษา (Class Schedules)
- จัดเก็บและแสดงตารางสอบกลางภาคและปลายภาค (Exam Schedules)
- บริหารจัดการข้อมูลห้องปฏิบัติการและสิ่งอำนวยความสะดวก (CE Rooms & Facilities)
- จัดเก็บประวัติและรีวิวการฝึกงานของนักศึกษาในสถานประกอบการ (Student Internships)
- ระบบจัดการสิทธิ์การเข้าถึงสำหรับผู้ดูแลระบบและผู้เขียนข่าวสาร (User Authentication & Roles)

### ผู้ใช้งานระบบ

| ประเภทผู้ใช้ | หน้าที่ |
|--------------|---------|
| ผู้ใช้ทั่วไป / นักศึกษา / ผู้ปกครอง (Public User) | เข้าถึงและเรียกดูข้อมูลประชาสัมพันธ์ ผลงาน ตารางเรียน/ตารางสอบ ข้อมูลห้องปฏิบัติการ และรีวิวการฝึกงาน |
| ผู้เขียนข่าวสาร / ตัวแทนชั้นปี (Writer / Cohort Editor) | เพิ่ม แก้ไข และจัดการข้อมูลตารางเรียน ข่าวสารกิจกรรม และผลงานเฉพาะชั้นปีที่ได้รับมอบหมาย |
| ผู้ดูแลระบบ (Admin) | บริหารจัดการข้อมูลหลัก เช่น นักศึกษา อาจารย์ ข่าวสาร ผลงาน ห้องปฏิบัติการ และตารางสอบ |
| ผู้ดูแลระบบสูงสุด (Superadmin) | จัดการผู้ใช้งาน กำหนดสิทธิ์การเข้าถึง ดูแลความปลอดภัย และบริหารจัดการฐานข้อมูลทั้งหมดในระบบ |

# ระยะที่ 2 การกำหนดระบบ (System Definition)

## ฟังก์ชันหลักของระบบ

- ระบบประชาสัมพันธ์ข่าวสาร กิจกรรม การแข่งขัน และทุนการศึกษา (News Portal)
- ระบบแสดงและค้นหารายชื่ออาจารย์และบุคลากรประจำสาขา (Teacher Directory)
- ระบบแสดงและค้นหารายชื่อนักศึกษาตามชั้นปี สายรหัส และตำแหน่ง (Student Directory & Tree)
- ระบบจัดแสดงผลงานและโครงงานนักศึกษา (Student Works Showcase)
- ระบบตรวจสอบตารางเรียนประจำภาคการศึกษาแบบปฏิสัมพันธ์ (Class Schedule Viewer)
- ระบบตรวจสอบตารางสอบกลางภาคและปลายภาค (Exam Schedule Tracker)
- ระบบข้อมูลห้องปฏิบัติการและจองใช้งานห้อง CE (Room & Facility Information)
- ระบบบันทึกและแชร์ประสบการณ์การฝึกงานในสถานประกอบการ (Internship Knowledge Base)
- ระบบยืนยันตัวตนและการจัดการสิทธิ์แบบ HttpOnly Cookie & RBAC (Auth & Access Control)

## ข้อมูลที่ต้องจัดเก็บ

- ข้อมูลบุคลากรและอาจารย์ (ชื่อ-นามสกุล, รูปภาพ, รายวิชา/ปีที่ดูแล, ช่องทางติดต่อ, ตำแหน่ง)
- ข้อมูลนักศึกษา (รหัสนักศึกษา, ชื่อ-นามสกุล, ชั้นปี, สายรหัส, ตำแหน่งในห้อง, รูปภาพ)
- ข้อมูลผลงานนักศึกษา (ปีการศึกษา, ขอบเขตผลงาน, ชื่อผลงาน, รายรายละเอียด, รูปภาพ, รหัสนักศึกษาผู้สร้าง)
- ข้อมูลข่าวสาร (หัวข้อ, หมวดหมู่, เนื้อหา, ลิงก์ภายนอก, รูปภาพ, วันที่เผยแพร่, ผู้เขียน)
- ข้อมูลตารางเรียนและตารางสอบ (รหัสวิชา, ชื่อวิชา, ชั้นปี, ภาคเรียน, วัน-เวลา, ห้องเรียน, ผู้สอน)
- ข้อมูลห้องปฏิบัติการ (ชื่อห้อง, Slug URL, สถานที่ตั้ง, รายละเอียด, คุณสมบัติ/อุปกรณ์, รูปภาพ)
- ข้อมูลการฝึกงาน (บริษัท, ตำแหน่ง, ระยะเวลา, สรุปประสบการณ์, สวัสดิการ/เบี้ยเลี้ยง, คะแนนรีวิว)

# ระยะที่ 3 การรวบรวมและวิเคราะห์ความต้องการ (Requirements Collection and Analysis)

## User Stories

### ระบบประชาสัมพันธ์และข้อมูลทั่วไป (Public Portal)

- ในฐานะ นักศึกษาทั่วไป ฉันต้องการ ค้นหาตารางเรียนและตารางสอบของชั้นปีตนเอง เพื่อให้ สามารถวางแผนการเรียนและการสอบได้อย่างแม่นยำ
- ในฐานะ ผู้ปกครอง/บุคคลภายนอก ฉันต้องการ ข้อมูลรายชื่ออาจารย์และช่องทางการติดต่อ เพื่อให้ สามารถติดต่อสอบถามข้อมูลการเรียนได้อย่างสะดวก
- ในฐานะ นักศึกษาชั้นปีที่ 3 ฉันต้องการ อ่านรีวิวและข้อมูลประสบการณ์การฝึกงานรุ่นพี่ เพื่อให้ มีข้อมูลประกอบการตัดสินใจเลือกสถานที่ฝึกงาน
- ในฐานะ นักเรียนที่สนใจเข้าศึกษา ฉันต้องการ รับชมผลงานและกิจกรรมของนักศึกษาในสาขา เพื่อให้ เข้าใจการเรียนการสอนและสร้างแรงบันดาลใจ
- ในฐานะ ผู้ใช้งานทั่วไป ฉันต้องการ ติดตามข่าวสารการแข่งขันและทุนการศึกษาล่าสุด เพื่อให้ ไม่พลาดโอกาสในการพัฒนาตนเองและรับทุน

### ระบบจัดการข้อมูลสำหรับตัวแทนชั้นปี (Writer / Cohort Admin)

- ในฐานะ ตัวแทนชั้นปี ฉันต้องการ อัปเดตตารางเรียนประจำภาคการศึกษาของชั้นปีตนเอง เพื่อให้ เพื่อนในชั้นปีได้รับข้อมูลตารางเรียนที่ถูกต้อง
- ในฐานะ ผู้สร้างสรรค์ข่าวสาร ฉันต้องการ โพสต์ข่าวประชาสัมพันธ์การแข่งขันพร้อมแนบรูปภาพและลิงก์ เพื่อให้ นักศึกษาเข้าร่วมกิจกรรมได้ทันเวลา

### ระบบการบริหารจัดการของผู้ดูแลระบบ (Admin & Superadmin)

- ในฐานะ ผู้ดูแลระบบ ฉันต้องการ จัดการข้อมูลรายชื่อนักศึกษาและอาจารย์ประจำสาขา เพื่อให้ ข้อมูลในระบบมีความเป็นปัจจุบันอยู่เสมอ
- ในฐานะ ผู้ดูแลระบบ ฉันต้องการ อัปเดตตารางสอบกลางภาคและปลายภาคของทุกชั้นปี เพื่อให้ นักศึกษาตรวจสอบตารางสอบได้อย่างถูกต้อง
- ในฐานะ ผู้ดูแลระบบสูงสุด ฉันต้องการ กำหนดสิทธิ์และสร้างบัญชีผู้ใช้งานในระบบ เพื่อให้ ควบคุมความปลอดภัยและการเข้าถึงข้อมูลของระบบได้
- ในฐานะ ผู้ดูแลระบบ ฉันต้องการ จัดการข้อมูลห้องปฏิบัติการและคุณสมบัติอุปกรณ์ เพื่อให้ ประชาสัมพันธ์การใช้งานห้องปฏิบัติการ CE ได้อย่างครบถ้วน

# Functional Requirements

1. ระบบต้องรองรับการยืนยันตัวตนผู้ดูแลระบบด้วย Username และ Password พร้อมส่งมอบ HttpOnly Cookie (`admin_token`)
2. ระบบต้องสามารถแสดงผลตารางเรียนแยกตามชั้นปี (ปี 1-4) และภาคการศึกษาได้อย่างถูกต้อง
3. ระบบต้องรองรับการแสดงผลตารางสอบกลางภาคและปลายภาค พร้อมแสดงประเภทการสอบ (จัดตามตาราง/ตารางนัดหมาย)
4. ระบบต้องมีฟังก์ชันค้นหาและกรองข้อมูลนักศึกษาตามชั้นปี สายรหัส และรหัสนักศึกษา
5. ระบบต้องรองรับการจัดเก็บและแสดงผลข่าวสารโดยแบ่งหมวดหมู่ (การแข่งขัน, ทุนการศึกษา, อื่นๆ)
6. ระบบต้องสามารถแสดงผลงานนักศึกษาโดยแบ่งตามขอบเขตโครงงาน (ระดับสาขา, กลุ่ม, เดี่ยว)
7. ระบบต้องรองรับการเชื่อมโยงข้อมูลการฝึกงานของนักศึกษากับตารางรายชื่อนักศึกษาผ่าน Foreign Key
8. ระบบต้องรองรับการอัปโหลดและจัดเก็บรูปภาพสำหรับข่าวสาร ผลงาน โปรไฟล์นักศึกษา/อาจารย์ และห้องปฏิบัติการ
9. ระบบต้องรองรับการจำกัดสิทธิ์การแก้ไขข้อมูลตามบทบาทผู้ใช้ (`superadmin`, `admin`, `writer`)
10. ระบบต้องรองรับการแสดงผลหลายภาษา (ไทย และ อังกฤษ) ในส่วนข้อมูลหลักของระบบ

# Non-Functional Requirements

- **Performance**: ระบบต้องสามารถตอบสนองต่อการสอบถามข้อมูล (API Response Time) ได้ภายใน 200 มิลลิวินาทีในสภาวะปกติ
- **Security**: ระบบต้องเข้ารหัสผ่านของผู้ใช้ด้วยอัลกอริทึมที่ปลอดภัย (Password Hashing) และใช้ Cookie แบบ `HttpOnly`, `SameSite=Lax`
- **Availability**: ระบบต้องมีความพร้อมใช้งาน (Uptime) ไม่น้อยกว่า 99.5% ผ่านโครงสร้างสถาปัตยกรรม Container (Docker & Nginx Proxy)
- **Usability**: หน้าจอผู้ใช้ (UI/UX) ต้องได้รับการออกแบบตามหลัก Responsive Design รองรับการใช้งานบนอุปกรณ์ทุกขนาด (Mobile/Tablet/Desktop)
- **Data Integrity**: ฐานข้อมูลต้องเปิดใช้งาน Foreign Key Constraints (`PRAGMA foreign_keys = ON`) เพื่อรักษาความสมบูรณ์ของข้อมูล

# ระยะที่ 4 การออกแบบฐานข้อมูลเชิงแนวคิด (Conceptual Database Design)

## Entity & Attributes

### ผู้ใช้งานระบบ (Users)

- `id` (รหัสอ้างอิงผู้ใช้)
- `username` (ชื่อผู้ใช้สำหรับเข้าสู่ระบบ)
- `email` (อีเมลผู้ใช้)
- `role` (สิทธิ์การใช้งาน: superadmin, admin, writer)

### นักศึกษา (Students)

- `student_id` (รหัสนักศึกษา 8 หลัก)
- `name_th` (ชื่อ-นามสกุล ภาษาไทย)
- `year` (ชั้นปีการศึกษา 1-4)
- `class_role` (ตำแหน่งในชั้นเรียน)
- `track` (รหัสสายรหัส)

### อาจารย์ประจำสาขา (Teachers)

- `id` (รหัสอาจารย์)
- `name_th` (ชื่อ-นามสกุล ภาษาไทย)
- `advise_years` (ชั้นปีที่ได้รับมอบหมายเป็นอาจารย์ที่ปรึกษา)
- `contact` (ช่องทางติดต่อ / อีเมล)

### ห้องปฏิบัติการ (Rooms)

- `slug` (Slug อ้างอิง URL ห้อง)
- `title_th` (ชื่อห้องปฏิบัติการ ภาษาไทย)

### ผลงานนักศึกษา (Works)

- `id` (รหัสผลงาน)
- `year` (ปีการศึกษา)
- `scope` (ขอบเขตผลงาน: branch, group, solo)
- `title` (ชื่อผลงาน / โครงงาน)

### ข่าวสารและทุนการศึกษา (News)

- `id` (รหัสข่าวสาร)
- `title` (หัวข้อข่าวสาร)
- `category` (หมวดหมู่ข่าวสาร)
- `body` (เนื้อหาข่าวสาร)
- `link` (ลิงก์ภายนอกที่เกี่ยวข้อง)
- `published_at` (วันที่เผยแพร่ข่าว)
- `author_username` (ชื่อผู้เขียนข่าวสาร)

### ตารางเรียน (Class Schedules)

- `id` (รหัสรายการตารางเรียน)
- `year` (ชั้นปีการศึกษา)
- `term` (ภาคเรียน)
- `day` (วันประจำสัปดาห์)
- `start_time` (เวลาเริ่มเรียน)
- `end_time` (เวลาสิ้นสุดการเรียน)
- `code` (รหัสวิชาเรียน)

## ความสัมพันธ์ของข้อมูล (Cardinality / Relationship)

- `users` [ 1 : N ] `news_items` (ผู้ใช้งานระบบ 1 คน สามารถสร้าง/โพสต์ข่าวสารได้หลายรายการ)

# ระยะที่ 6 การออกแบบฐานข้อมูลเชิงกายภาพ (Physical Database Design)

## ระบบจัดการฐานข้อมูล (DBMS)

- SQLite 3 (เปิดใช้งาน WAL Journal Mode และ Foreign Key Constraints)

## Primary Key

- `teachers.id` (INTEGER AUTOINCREMENT)
- `students.id` (INTEGER AUTOINCREMENT)
- `works.id` (INTEGER AUTOINCREMENT)
- `news_items.id` (INTEGER AUTOINCREMENT)
- `class_schedules.id` (INTEGER AUTOINCREMENT)
- `exam_schedules.id` (INTEGER AUTOINCREMENT)
- `users.id` (INTEGER AUTOINCREMENT)

## Foreign Key

- `internship_students(student_id)` → `students(student_id)`
- `news_items(author_username)` → `users(username)`
- `works(author_ids)` → `students(student_id)` (JSON Array Representation)
- `class_schedules(room)` → `rooms(slug)` (Logical Foreign Key)

## การสร้าง Index

- `CREATE UNIQUE INDEX idx_students_student_id ON students(student_id);`
- `CREATE UNIQUE INDEX idx_users_username ON users(username);`
- `CREATE UNIQUE INDEX idx_users_email ON users(email);`
- `CREATE UNIQUE INDEX idx_exam_schedules_ytc ON exam_schedules(year, term, code);`

## การสำรองข้อมูล

- ระบบสำรองข้อมูลไฟล์อัตโนมัติด้วย SQLite Online Backup API เป็นประจำทุกวัน
- การทำสำเนาและจัดเก็บไฟล์บันทึกการเปลี่ยนแปลง (WAL File Archiving) ไปยังพื้นที่จัดเก็บข้อมูลสำรอง

## ความปลอดภัย

- การเข้ารหัสผ่านผู้ใช้ด้วย Argon2 / Bcrypt ในระดับแอปพลิเคชัน (FastAPI)
- การป้องกันการโจมตี Session Hijacking ผ่านการใช้งาน HttpOnly และ SameSite Cookie
- การป้องกัน SQL Injection โดยใช้ Parameterized Queries ผ่าน SQLite API
- การควบคุมสิทธิ์การเข้าถึงข้อมูลตามบทบาทผู้ใช้ (Role-Based Access Control - RBAC)

# ส่วนที่ต้องดำเนินการในโครงงาน

## 1. วิเคราะห์ระบบ

- ศึกษากระบวนการประชาสัมพันธ์และโครงสร้างการจัดเก็บข้อมูลเดิมของสาขาวิชาวิศวกรรมคอมพิวเตอร์
- รวบรวมปัญหาจากการใช้งานระบบเดิม เช่น ความกระจัดกระจายของข้อมูลตารางเรียน ข้อมูลข่าวสาร และผลงาน
- กำหนดเป้าหมายการพัฒนาระบบกลางเพื่อรวมศูนย์ข้อมูลทุกส่วนของสาขาเข้าด้วยกัน
- ประเมินความต้องการทรัพยากรระบบ เทคโนโลยีที่ใช้ และสถาปัตยกรรมระบบ (Next.js + FastAPI + SQLite + Docker)

## 2. วิเคราะห์ความต้องการ

- เก็บรวบรวมความต้องการจากผู้ใช้งาน 3 กลุ่ม ได้แก่ นักศึกษาทั่วไป ตัวแทนชั้นปี และอาจารย์/ผู้ดูแลระบบ
- จัดทำ User Stories และจำแนกประเภทความต้องการออกเป็น Functional Requirements และ Non-Functional Requirements
- กำหนดสิทธิ์การเข้าถึงและการทำงานของผู้ใช้แต่ละระดับ (`superadmin`, `admin`, `writer`, `public`)
- สรุปขอบเขตฟังก์ชันการทำงานหลักของระบบทั้ง 8 โมดูล

## 3. ออกแบบฐานข้อมูล

- กำหนดโครงสร้าง Entity หลักของระบบจำนวน 9 เอนทิตี ได้แก่ Users, Students, Teachers, Works, News, Class Schedules, Exam Schedules, Rooms, Internships
- กำหนด Attribute ของแต่ละ เอนทิตี พร้อมระบุประเภทข้อมูลและข้อกำหนด (Constraints)
- กำหนดความสัมพันธ์ระหว่างเอนทิตี (Cardinality / Relationship) ทั้งแบบ 1:1, 1:N และ N:M (ผ่าน JSON)
- ตรวจสอบความถูกต้องและปรับโครงสร้างแบบจำลองเชิงแนวคิดให้ครอบคลุมความต้องการของระบบ

## 4. ออกแบบตารางฐานข้อมูล

- แปลงแบบจำลองเชิงแนวคิด (Conceptual Model) เป็นแบบจำลองเชิงตรรกะ (Logical Model) และเชิงกายภาพ (Physical Model)
- ทำการปรับบรรทัดฐานฐานข้อมูล (Database Normalization) ให้อยู่ในระดับ 3NF
- สร้างไฟล์ DDL (`schema.sql`) กำหนดการสร้างตาราง Primary Key, Foreign Key และ UNIQUE Constraints
- ออกแบบและสร้าง Index สำหรับคอลัมน์ที่มีการค้นหาบ่อยเพื่อเพิ่มประสิทธิภาพการคิวรีข้อมูล

## 5. ออกแบบหน้าจอ

- ออกแบบโครงร่างหน้าจอ (Wireframe & Mockup) สำหรับฝั่งผู้ใช้งานทั่วไป (Public UI) เน้นความทันสมัย ปรับโหมดมืด/สว่างได้
- ออกแบบหน้าจอแดชบอร์ดบริหารจัดการสำหรับผู้ดูแลระบบ (Admin Portal) ในการจัดการข้อมูลหลัก
- ออกแบบหน้าจอแสดงตารางเรียนและตารางสอบให้ตอบสนองแบบปฏิสัมพันธ์ (Interactive Schedule Grid)
- จัดทำโครงสร้างการนำทาง (Navigation Structure) และองค์ประกอบตามหลักการออกแบบ UX/UI

## 6. พัฒนาระบบ

- พัฒนาส่วนแบ็กเอนด์ (Backend RESTful API) ด้วย Python FastAPI และ SQLite 3
- พัฒนาส่วนฟรอนต์เอนด์ (Frontend Web Application) ด้วย Next.js, React และ Vanilla CSS
- พัฒนาระบบยืนยันตัวตนและการจัดการสิทธิ์แบบ HttpOnly Cookie Security
- ติดตั้งและตั้งค่า Nginx Reverse Proxy และ Docker Container สำหรับการปรับใช้ระบบจริง (Deployment)

## 7. ทดสอบระบบ

- ทดสอบการทำงานของฟังก์ชันหลักทั้งหมด (Functional Testing) ตามข้อกำหนด Functional Requirements
- ทดสอบความปลอดภัยของระบบ (Security Testing) ในการเข้าถึงส่วนผู้ดูแลระบบและการป้องกัน SQL Injection
- ทดสอบการตอบสนองและความเร็วของระบบ (Performance & Stress Testing) ในการคิวรีข้อมูล
- ทดสอบการใช้งานบนอุปกรณ์และขนาดหน้าจอที่แตกต่างกัน (Cross-Device & Responsive Testing)

## 8. จัดทำเอกสารและนำเสนอ

- จัดทำเอกสารคู่มือการติดตั้งและการใช้งานระบบ (Deployment & User Guide)
