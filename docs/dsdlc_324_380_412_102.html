1.1 & 1.2 ปัญหาของระบบเดิม (Current Pain Points)

วิเคราะห์สภาพการณ์เดิมก่อนการพัฒนาระบบฐานข้อมูลกลาง

01
Data Fragmentation

ข้อมูลแยกเก็บใน Excel, เอกสารกระดาษ, PDF Drive และโซเชียลมีเดีย

02
Redundancy

ข้อมูลนักศึกษา อาจารย์ ขัดแย้งกัน ขาดการเชื่อมโยงระบบกลาง

03
Access Control

ไม่มีระบบพิสูจน์ตัวตน แบ่งสิทธิ์ไม่ชัดเจน เสี่ยงต่อการแก้ไขข้อมูล

04
Maintenance

ภาระการอัปเดตตารางเรียน/สอบด้วยมือ เกิดความผิดพลาดสูง

1.3 วัตถุประสงค์ระบบใหม่ (System Objectives)

เป้าหมายหลักของการออกแบบและติดตั้งระบบฐานข้อมูล

CENTRAL DATABASE
รวมข้อมูลเป็นหนึ่งเดียว

จัดเก็บข้อมูล 9 เอนทิตีหลัก (ผู้ใช้ นักศึกษา อาจารย์ ผลงาน ข่าวสาร ตารางเรียน ตารางสอบ ห้อง ฝึกงาน) ในฐานข้อมูลเดียว

SECURITY & RBAC
ควบคุมสิทธิ์เข้มงวด

ยืนยันตัวตนด้วย HttpOnly Cookie Token + Role-Based Access Control (Superadmin, Admin, Writer, Public)

PORTAL & DASHBOARD
Public Portal & Admin

แสดงตารางเรียน ตารางสอบ ข่าวสาร ทุนการศึกษา ผลงาน

วงจรพัฒนาระบบฐานข้อมูล DSDLC (6 Phases)

กระบวนการพัฒนา 6 ระยะตามมาตรฐาน Database Systems Life Cycle

2.1 ผังความสัมพันธ์เอนทิตี (ER Diagram)

ภาพรวม Entity Relationship Diagram สำหรับระบบฐานข้อมูล CE50

2.2 การออกแบบเชิงแนวคิด (Entity Relationships)

เอนทิตีหลัก 9 ตารางและความสัมพันธ์ Cardinaility 1:N

2.3 คัดเลือกซอฟต์แวร์ DBMS (SQLite 3)

เหตุผลทางสถาปัตยกรรมในการเลือก File-Based Engine สำหรับ CE Portal

LIGHTWEIGHT
Embedded File Engine

ไม่ต้องรัน Background Service แยก ประหยัด RAM/CPU บน Server ประสิทธิภาพสูงสำหรับการจัดเก็บข้อมูลภาควิชา

WAL MODE
Write-Ahead Logging

เปิดใช้ PRAGMA journal_mode = WAL; ทำให้อ่านและเขียนข้อมูลพร้อมกันได้โดยไม่เกิด DB Lock

INTEGRITY
Foreign Key Enforcement

เปิดใช้ PRAGMA foreign_keys = ON; บังคับ Referential Integrity ป้องกันข้อมูลกำพร้าในระบบ

CONTAINER READY
Docker Volume Integration

Mount ไฟล์ .db ผ่าน Docker Volume ทำการสำรองข้อมูล (Online Backup) และ Migration ได้สะดวกรวดเร็ว

2.4 ตารางฐานข้อมูล 3NF (Logical Schema)

โครงสร้างตารางที่ผ่านการปรับบรรทัดฐาน 3NF ลดความซ้ำซ้อนข้อมูล

Table Name Primary Key Foreign Keys & Constraints Description
users id (INTEGER) username (UNIQUE), role CHECK สิทธิ์ผู้ใช้งาน (superadmin, admin, writer)
students id (INTEGER) student_id (UNIQUE), Advisor FK ข้อมูลนักศึกษา ชั้นปี สายรหัส สาขา
class_schedules id (INTEGER) room FK → rooms.slug ตารางเรียนประจำภาคการศึกษา
exam_schedules id (INTEGER) room FK → rooms.slug ตารางสอบกลางภาค และปลายภาค
internships id (INTEGER) student_id FK → students.id ประวัติและรีวิวการฝึกงานนักศึกษา

3 - 6 : การติดตั้งและดูแลระบบ

การนำไปใช้ ทดสอบ ติดตั้งใช้งานจริง และบำรุงรักษาฐานข้อมูล

PHASE 3
Implementation

สร้าง FastAPI Endpoints, Python Migration Script และ Seed ข้อมูลเริ่มต้น (นักศึกษา อาจารย์ ตารางเรียน)

PHASE 4
Testing & Eval

ทดสอบ Unit/Integration, ตรวจสอบ Foreign Key Integrity แบบเร็วโคตรๆ

PHASE 5
Deployment

รันบน Docker Container + Nginx Proxy และเปิดใช้งาน

PHASE 6
Maintenance

สำรองข้อมูลไฟล์ .db ผ่าน Docker Volume, ตรวจวัดสถานะระบบ และรองรับการอัปเดต Schema ในอนาคต

สถาปัตยกรรมระบบ (System Architecture)

การเชื่อมโยงระบบระหว่าง Next.js, FastAPI, SQLite และ Docker Nginx Proxy
